# Markdown 速查（本站实测）

下面标注 ✅ 的写法都是在这个站点（Astro + remark-gfm + KaTeX）实际构建验证过的，⚠️ 是需要留意的坑。

写新文章：`npm run new -- <文件名> "标题"`，或在 VS Code 里新建 `.md` 后用 `post` 片段展开模板。

## 标题与锚点

✅ `#` 到 `######` 六级标题，且每个标题会自动生成 `id`——中文标题的 id 就是中文本身，所以可以直接做页内跳转：

```md
[跳到「代码」那节](#代码)
```

文章页顶部已经渲染了 `title`，正文建议从 `##` 开始，一篇文章里只出现一个 `#` 会更整齐。

## 强调与行内元素

✅ 全部支持：

```md
**加粗**  *斜体*  ***加粗斜体***  ~~删除线~~  `行内代码`
```

## 列表

✅ 无序用 `-`（或 `*`、`+`），有序用 `1.`，缩进两格表示嵌套：

```md
- 第一项
  - 嵌套项

1. 有序第一项
2. 有序第二项
```

✅ 任务列表会渲染成复选框：

```md
- [x] 已完成
- [ ] 未完成
```

## 链接

```md
[链接文字](https://example.com)
https://example.com               # 直接写网址也会自动识别成链接
```

## 图片

图片放哪儿、怎么写，实测结果如下：

| 图片位置 | 写法 | 构建后 |
| --- | --- | --- |
| `public/images/foo.png` | `![说明](/images/foo.png)` | 原样拷贝，路径固定，不压缩 |
| `src/assets/foo.png` | `![说明](../../assets/foo.png)` | 自动压缩、转 WebP、加哈希、加懒加载和宽高 |
| 和文章放同一目录 | `![说明](./foo.png)` | 同上，图片跟着文章走，最省心 |

三种常用写法：

```md
![图片说明](/images/foo.png)                      # 最省事

[![图片说明](/images/foo.png)](/images/foo.png)    # 点击看大图

<figure>
<img src="/images/foo.png" width="320" alt="图片说明">
<figcaption>图注写这里</figcaption>
</figure>
```

⚠️ 想控制宽度只能用 HTML 的 `<img width="...">`，Markdown 语法本身不支持设置尺寸。代价是 HTML 标签里的路径**不会被自动优化**：

- 用 HTML 标签时，图片请放在 `public/`，路径写 `/images/foo.png`
- HTML 标签里写 `../../assets/foo.png` 这类相对路径**不生效**，线上会 404
- 想让下载的文件更小，要么自己先压缩再放进 `public/`，要么改用 Markdown 语法让构建时生成 WebP

## 引用、分隔线与换行

```md
> 引用
>> 嵌套引用

---                 # 分隔线（三个以上减号）

行尾打两个空格  
这一行会另起一行
```

## 表格

✅ 支持，并且支持列对齐：

```md
| 左对齐 | 右对齐 | 居中 |
| :--- | ---: | :---: |
| 内容 | 123 | 中 |
```

冒号的位置决定对齐：左边有 `:` 左对齐，右边有 `:` 右对齐，两边都有居中。

## 代码

✅ 行内代码用反引号包裹。✅ 代码块用三个反引号，**写上语言名才会高亮**：

````md
```cpp
int main() {
    return 0;
}
```
````

常用语言名：`cpp`、`c`、`python`、`js`、`ts`、`bash`、`html`、`css`、`json`、`yaml`、`text`（`text` 表示不特殊高亮）。

## 数学公式

✅ 行内公式用 `$...$`，✅ 独立成行用 `$$...$$`：

````md
行内：$a^2 + b^2 = c^2$

$$
\int_0^1 x^2 \, dx = \frac{1}{3}
$$
````

⚠️ 坑：正文里**成对的 `$` 会被当成公式**。写价格之类的要转义：

````md
这件 $100 元，那件 $200 元      ← 两个 $ 之间的内容会变成公式
这件 \$100 元，那件 \$200 元    ← 正确
````

## 折叠块

✅ `<details>` 可用，而且块内的 Markdown 照常解析（列表、代码块都能正常渲染）。这里不需要 Jekyll 时代的 `markdown="1"`：

````html
<details>
<summary>点击展开完整代码</summary>

```cpp
int main() {
    return 0;
}
```

</details>
````

## 脚注

✅ 支持，脚注内容会集中显示在文章末尾：

```md
正文里提到某个点[^1]。

[^1]: 这是脚注内容。
```

## 容易忘的几条

- **空行分段**：段与段之间必须空一行，否则会被当成同一段
- **转义**：想原样显示 `*`、`_`、`#`、`$` 等符号，前面加反斜杠，例如 `\*`
- **文件名决定 URL**：`src/content/posts/foo.md` → `/posts/foo/`，改文件名等于改 URL；页面显示的标题取 frontmatter 里的 `title`
- **tags 必须是数组**：`tags: [算法, 数学]`，写成字符串会导致构建失败
- **draft**：`draft: true` 时只有 `npm run dev` 能看到，线上不会出现
